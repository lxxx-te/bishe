Lesson 02 · 处理层

一篇报道如何变成「事件」

用你系统里真实的事件 #132 讲透 P3 去重：三家不同媒体的报道，为什么能合成一个事件？

本课目标：能讲清 Attach（挂载）和 Spawn（新建事件）的分叉逻辑，以及阈值 0.90 是什么。

真实案例：事件 #132

系统里 GET /api/events/132 返回的真实数据——三个来源、三篇不同标题的报道，全部属于同一个事件：

来源标题
中国新闻网“地球的红飘带”临展画作自带附文存在错误 浙江省博物馆致歉
澎湃新闻马上评｜一周内两次道歉，浙江省博不该以这样的方式出圈
澎湃热榜浙江省博物馆长征主题版画展出现多处文字错误，协办方致歉

三篇报道文字完全不同，但它们讲的是同一件事。P3 的工作就是发现这件事，并把三篇都挂到同一个事件下 （1 事件 : N 报道）。

分叉逻辑：挂载 or 新建？

核心代码在 app/services/dedup.py:112 的 dedup_one()，逻辑只有三步：

candidates = await _find_candidate_events(session, keywords)   # 1. 用关键词找候选事件
# 2. 对每个候选事件做向量余弦相似度，取最高
sim = _cosine(report.embedding, ev.embedding)

if best_event and best_sim > DEDUP_THRESHOLD:   # 3. 阈值判断
    await _attach_to_event(session, report, best_event, keywords)  # → Attach
    return {"action": "attach", ...}

event = await _spawn_event(session, report, keywords)  # 否则 → Spawn

关键点：

  • 关键词是第一道闸：新报道的关键词与某事件关键词无重叠，直接跳过向量计算（省 LLM/向量调用）
  • 相似度 > 0.90 → Attach：挂到最相似的事件下
  • ≤ 0.90 → Spawn：不是同一件事，新建事件，自己当首篇报道
  • 阈值 0.90 不是拍脑袋：dedup.py:26 注明来自 100 对人工标注黄金集调优（precision 0.929 / recall 1.000 / F1 0.963）

Attach 之后发生了什么

挂载不是简单记个 event_id——_attach_to_event()（dedup.py:90-109）同步做四件事：

动作效果
source_count +1热度上涨：事件 #132 的 source_count = 3
关键词并集保留最多 6 个（GIN 索引效率）
事件发布时间取最小保证事件时间是"最早报道"时间
后台重算摘要 + 重 embed合并所有报道摘要，避免首篇措辞偏置事件向量中心（Q 系列决策）
