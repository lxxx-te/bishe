BISHE · PROJECT TOUR · 第 3 课

你的毕设仓库，每个文件夹在干什么

目标对齐 MISSION：答辩时被问「这个目录/模块是干什么的」，你能指着任何文件立即讲清职责。本文按「系统本体 → 证据链 → 文档弹药 → 教学区」四块讲，每个文件名都是真的，数字都可复核。

〇、先看全景~/bishe

一句话定位：多源新闻事件的向量聚合与检索系统。FastAPI + PostgreSQL/pgvector + BGE(CPU) + DeepSeek + Vue3。

采集rss/newsapi→ 处理摘要·向量·关键词→ 聚合去重 spawn/attach→ 检索预过滤·ANN·重排→ 生成受约束+SSE→ 输出API/简报/RSS/前端
~/bishe/ ├── app/ 后端本体（五层管道的 Python 实现） ├── frontend/ Vue3 前端 ├── scripts/ 评测证据链工厂（7 个脚本） ├── data/ 冻结的评测资产（gold + 结果 JSON） ├── docs/ 文档弹药库（HANDOFF/PITFALLS/thesis 五件套） ├── tests/ pytest 单测（10 个） ├── configs/ RSS 源清单 feeds.yaml ├── lessons/ learning-records/ assets/ + MISSION/NOTES/RESOURCES 教学工作区 └── CONTEXT.md · README.md · .env · requirements.txt 根文件
记忆钩子：app+frontend 是「系统」，scripts+data 是「证据」，docs 是「弹药」，lessons 系列 是「你的私教课现场」。答辩四问——系统怎么跑？结论怎么来？设计为什么？你学到了什么？——各对应一块。

一、后端本体app/

五层管道全部住在这里。入口 main.py 挂载所有路由；core/config.py 是唯一配置中心（读 .env）。

api/ — 路由层（HTTP 门面）

文件职责答辩要点
health.py存活检查 /api/health演示前 ping 它确认后端活着
ingest.pyP1触发采集入库演示日早晨重采就是调它
p2.pyP2处理编排（摘要/向量/关键词）调用 services 三个工人
p3.pyP3聚合编排（去重 spawn/attach）事件诞生的地方
p4.pyP4合并摘要（多源事件 LLM 合并）merged_summary 只在 ≥2 源事件上跑，省 LLM 钱
events.py事件列表/详情 API排序键 = 多源度 COUNT(DISTINCT source_site)，字段叫 source_breadth
digest.py每日简报 /api/digest按多源度降序取 Top-10，复用 merged_summary 零新增 LLM
feed.py输出RSS 事件流 /feed/events.rss每条 = 一个事件，链接指向首篇原文
rag.pyRAG问答 /api/rag/ask（SSE 流式）请求体字段是 query 不是 question
reports.py · user.py报道列表 · 用户兴趣标签（仅显式勾选）不做行为画像是隐私设计决策

services/ — 干活的工人

文件职责关键细节
ingest/rss.py拉 RSS/解析 description没有全文抓取器——raw_text 就来自 RSS 摘要
ingest/persist.py准入闸门 has_complete_text()残句/纯标题/纯署名拒收；去尾引号后必须停在 。！？… 上。8月新增，防幻影事件
summarize.pyLLM 摘要 + 电头剥离剥「中新网X月X日电 题：」；LLM 失败降级 fallback（现仅 7 条且完整）
embed.pyBGE-small-zh 向量化（CPU）报道级 + 事件级（重挂载后异步重算中心）
keywords.pyN-gram 关键词提取闸门匹配的弹药，GIN 索引加速
dedup.pyP3核心：关键词闸门 + 向量 ANN阈值 0.90 从 settings 读（刚修的死配置）；重叠→attach，否则→spawn
p4.py多源事件 LLM 合并摘要动机：首篇措辞不能偏置事件表示
rag/retrieval.py三段检索前两段时间预过滤 → pgvector ANN Top-20 → bge-reranker Top-5
rag/answer.py受约束生成 + 强制 [事件#X] 引用幻觉防线的最后一道；SSE 逐 token 推给前端
rag/dailylimit.pyDeepSeek 每日限额计数对应 data/rag_daily_counter.json
fact_extract.pylegacy5W1H 抽取已移出主链路（faithfulness 0.978→0.941 的代价换来简洁），代码保留作移除记录

其余

models/models.py 就两张表：news_report（每篇报道一行，含 embedding）和 news_event（聚合事件，含 merged_summary / keywords / embedding，HNSW+GIN+三列 btree 索引）。db/init_schema.py 建表，db/session.py 给 asyncio session。eval/ 目前是空的（评测逻辑都住在 scripts/）。core/config.py 用 pydantic-settings 读 .env——dedup 阈值等所有魔法数字的合法居所。

一条数据的完整流向（答辩高频题）：feeds.yaml 定义源 → rss.py 拉取 → persist.py 过闸门 → summarize+embed+keywords 三件套加工 → dedup.py 决定 spawn 新事件还是 attach 进旧事件 → p4 给多源事件合并摘要 → events/digest/feed 三个出口 → 前端卡片。RAG 线：用户问题 → retrieval 三段 → answer 约束生成 → SSE 流回 RagChatView。

四、冻结的评测资产data/

「不改数据不重跑」裁决的物理载体：评测数字 = 这些文件的快照，配套数据库快照 news_aggregator_eval。

文件是什么注意
rag_gold.csv检索评测 gold（50行）含 13 组完全重复题对——不是 bug 是标注工具产物，已如实写进论文
dedup_gold.csv去重评测 gold（n=100）tune 脚本的唯一输入，仓库自带=可复现
rag_eval_results.json48 行逐题结果（现行）faithfulness 0.941
rag_eval_results_v1_5w1h.json5W1H 移除前的对照faithfulness 0.978——04 文件取舍表的原始证据
rag_ablation_results.json / .csv消融 5 行0.353→0.452
rag_daily_counter.jsonDeepSeek 当日用量演示前查限额
主库 ≠ 评测库：主库 news_aggregator 已清理为 187 报道/166 事件（准入闸门上线后），评测数字基于旧快照 200/176。若重跑评测必须连快照 news_aggregator_eval，02 文件已声明此口径。

六、测试与配置tests/ · configs/

tests/ 三个文件共 10 个用例：test_health（存活）、test_ingest（准入闸门：完整句放行、残句拒收、URL 去重、空文本拒收）、test_rag（检索管道装配）。跑法：.venv/bin/python -m pytest。注意 venv 必须用项目内的 ~/bishe/.venv/bin/python，系统 python3 缺 pydantic_settings。

configs/feeds.yaml 是全部 RSS/NewsAPI/RSSHub 源清单——采集层的唯一配置入口，加源改这里。
