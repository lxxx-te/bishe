Git 演进史与测试盲区：提交记录里的答辩叙事

代码会说话，提交历史会讲故事。这一课把 git log 当考古现场：第一幕的两日冲刺怎么讲成答辩开场白，第二幕的未提交改动说明什么，测试盲区哪些该补、哪些可以坦然承认。

⑤ 盲区分级：哪些该补，哪些坦然承认

盲区风险处置建议
dedup_one 三岔口（spawn/attach/skip）最高危：核心算法零单测，阈值边界（>0.90 严格大于）全靠手验补 3 个纯函数级用例即可，无需 DB（候选列表 mock 进去）
retrieve 三段漏斗时间窗解析、Top-20 SQL、rerank 降级路径无回归保护至少测「rerank 抛异常时退回 ANN 序」这一条降级路径
digest/events/feed 端点排序口径（breadth）刚改过，无防回归网各 1 条冒烟足够
summarize fallback 分支中危：降级行为有 PITFALLS 记录但无断言可选
P4 LLM 合并质量外部依赖重，单测只能测假 LLM坦然承认：这层的正确性由评测集兜底，不硬造单测
论文话术：两层验证体系 被问「测试怎么这么少」时的标准答案：本系统的验证分两层——单元测试守行为不变量（幂等、拒收、引用越界必报、异常必降级），评测体系守效果指标（set recall@5、refusal accuracy、faithfulness、消融）。P4 这类 LLM 主导环节，单测只能证明「代码跑了」不能证明「结果对」，所以投入放在了可复现评测上。这是资源分配的自觉选择，不是遗漏。

⑥ 三问自测

Q1. 「最近一周政治新闻」误拒不怪拒答逻辑——那两条提交/文件分别是什么？
答案

根因链在 retrieval.py 的 _parse_time_window 用墙钟 datetime.now() 解析时间词 × 评测用的是 7 月冻结快照。证据在 data/rag_eval_results.json 那两行 refusal=True 且 gold 非空的 broad 题（对应全量行口径 46/48=0.958 里扣掉的 2 分）。

Q2. 如果评委说「你们只有 10 个测试」，最有力的一句话回应？
答案

「单元测试守行为不变量，评测集守效果指标——dedup 阈值是在 100 对金标上调出来并可离线重放的，这比多写十个 mock 单测更能证明系统正确。」然后主动指出已知盲区（dedup_one 三岔口）和补法，显示的不是辩护而是清醒。
